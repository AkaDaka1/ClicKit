## Следующие шаги (по порядку)

1. **M0 (остаток):** Создать структуру каталогов (`app/`, `core/`, `gui/`, `bridge/`,
   `resources/`, `tests/`), `requirements.txt`,
   точку входа `python -m app` с пустым окном PySide6; заполнить секцию «Команды» в `AGENTS.md`.
2. **Организационное:** переименовать локальную папку `AutoClicker` → `ClicKit`,
   создать GitHub-репозиторий `ClicKit` (описание и topics — см. ниже), подключить remote и запушить `master`.
3. **M1:** Абстракция `InputBackend` + реализация на pyautogui; `hotkeys.py`
   (глобальный стоп по F6); `executor.py` — выполнение простейшей последовательности
   кликов в воркере. Консольная проверка без GUI.
4. **M2:** Главное окно с двумя режимами; «Простой режим»: координаты (пикер),
   интервал, кнопка мыши, число повторов, старт/стоп по хоткею и кнопкой; трей-иконка.
5. Далее — по `ROADMAP.md` (M3: IR-сценарии, M4: Blockly, M5: упаковка).

## Известные проблемы / вопросы

- [ ] Выбрать конкретные версии PySide6 и QtWebEngine (тяжёлая зависимость,
      нужен план Б на случай проблем со сборкой PyInstaller).
- [ ] Решить, нужен ли `mouse` как третий бэкенд ввода (pyautogui иногда
      конфликтует с полноэкранными играми — возможно, понадобится raw input).
- [ ] Античит-риски: документировать, что проект предназначен для
      некоммерческого/офлайн-использования. (✅ частично: дисклеймер добавлен в README)
- [ ] Выбрать лицензию (планируется MIT; учесть LGPL у PySide6 и Apache-2.0
      у vendored Blockly) и добавить файл `LICENSE` до публикации на GitHub.
- [ ] Переименовать локальную папку `AutoClicker` → `ClicKit` (делать вне активной
      сессии агента, чтобы не сломать рабочую директорию) и создать remote `ClicKit`.
