# AGENTS.md — Инструкции агенту на каждую новую сессию

## Перед началом работы — обязательно
1. Прочитай **`AI_CONTEXT.md`** — единый источник правды: суть, стек, архитектура, правила кодинга.
2. Прочитай **`PROGRESS.md`** — текущий статус и следующие шаги; задачи начинай оттуда.
3. Загляни в **`ROADMAP.md`** — пойми, к какой вехе (M0–M11) относится задача.

## Во время и после работы
- Значимые изменения → обнови `AI_CONTEXT.md` и `PROGRESS.md` (запись в журнале).
- Новые категории артефактов (кэши, сборки, логи, локальные данные) → обнови `.gitignore`.
- При необходимости (новые фичи, изменение установки/запуска, статуса проекта) → обнови `README.md`.
- Код: Python 3.11+, type hints везде, ruff (lint + format);
  идентификаторы на английском, комментарии и документация на русском.
- `core/` не импортирует `gui/` и PySide6; сценарии исполняются только в фоновом потоке.
- Коммиты: одна фича = один коммит, формат `type: subject` (feat/fix/docs/refactor/test/chore).
- Значимые архитектурные решения не принимай молча — фиксируй в `AI_CONTEXT.md` §3.3;
  при неясных требованиях спрашивай пользователя.

## Планы вех (plans/)

- Когда пользователь просит план перед новым этапом (M0, M1, ...) —
  создать подробный план в `plans/` (имя: `M<#>-<slug>.md`,
  например `plans/M1-core-engine.md`): цель и критерий готовности,
  согласованные параметры, модули с описанием интерфейсов, решения (ADR),
  список коммитов, чек-лист приёмки, **граф задач** (таблица: ID, задача,
  зависимости, чекпоинт «done = …», статус + схема параллельных волн).
- **`plans/` — публичная часть репозитория** (не gitignored): планы вех
  коммитятся вместе с кодом и индексируются в `plans/README.md`. Это нужно,
  чтобы был виден процесс: цель → ADR → граф задач → чекпоинт. Статус ✅
  ставится только после пройденного чекпоинта; «запланировано» ≠ «сделано».
- **Запуск задач из разных сессий** (практика, 2026-10-31): пользователь
  запускает задачи вехи по отдельности в разных сессиях — «выполни T1.2»
  или «выполни следующую доступную задачу». Агент берёт только названную
  задачу и только если все её зависимости закрыты (статус ✅), в конце
  обновляет строку задачи в плане, дописывает «Журнал задач» в плане и
  делает запись в `PROGRESS.md`. Задача без пройденного чекпоинта не
  помечается ✅.
- Перед началом работы над вехой или любым её пунктом — сначала прочитать
  `plans/M<#>-*.md` соответствующей вехи и работать по нему.
- Если работа уводит от плана или план устарел — сначала обновить план,
  потом продолжать работу.

## Команды

- Установка зависимостей: `pip install -r requirements.txt`
- Сервис (M7): `pip install -r requirements-service.txt` и
  `uvicorn service.app.main:app` (нужен `CLICKIT_API_KEY`, см. `docs/api.md` §9)
- Тесты сервиса (M7): `pip install -r requirements-service-test.txt` и
  `python -m pytest tests/service`
- Образ сервиса (M7): `docker build -f docker/Dockerfile.service -t clikit-service:local .`
- Сборка релиза: `pip install -r requirements-build.txt` и `python scripts/build_exe.py --both`
- Запуск: `python -m app`
- Проверки: `ruff check .` + `ruff format --check .` + `python -m pytest`
- Проверка релиза: `python scripts/verify_release.py --tag v<версия> --smoke`
- Форматирование: `ruff format .`
- Скриншоты для README: `python scripts/make_screenshots.py` (offscreen)
- CI/CD: GitHub Actions (`windows-latest`) — `.github/workflows/ci.yml` (PR и
  `master`) и `.github/workflows/release.yml` (тег `v<APP_VERSION>`); схема в
  `AI_CONTEXT.md` §3.4
