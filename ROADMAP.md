# ROADMAP.md — Дорожная карта ClicKit

Концептуальный план от пустого репозитория до упакованного приложения
с визуальным блочным программированием. Детали реализации каждого модуля
уточняются перед стартом соответствующей вехи (не раньше).

---

## M0 — Инициализация структуры репозитория
**Цель:** скелет проекта, который запускается и готов к разработке.
- Структура каталогов по `AI_CONTEXT.md` §3.2.
- `requirements.txt` (PySide6, pyautogui, pynput), `README.md` (✅ `.gitignore` уже создан).
- Точка входа `python -m app`: пустое `QMainWindow` открывается и закрывается.
- Настройка ruff.

**Критерий готовности:** `python -m app` показывает пустое окно; первый коммит в git.

## M1 — Базовый движок кликов (core, без GUI)
**Цель:** надёжное ядро эмуляции ввода.
- ABC `InputBackend`: `click`, `double_click`, `move_to`, `drag_to`, `press_key`, `scroll`.
- Реализация на pyautogui (pynput — только глобальные слушатели, ADR №7).
- `hotkeys.py`: глобальные хоткеи старт/стоп (pynput listener в отдельном потоке).
- `executor.py`: воркер с потокобезопасным флагом остановки; выполняет плоский
  список команд (клик, пауза, движение) с заданным интервалом/повторами.

**Критерий готовности:** скрипт-демо кликает в заданную точку N раз и мгновенно
останавливается по F6 из любого приложения.

## M2 — GUI: главное окно и «Простой режим» (MVP)
**Цель:** продукт уже полезен как обычный автокликер.
- Главное окно с переключением режимов (Простой / Редактор-заглушка).
- Простой режим: координаты X/Y + пикер («наведись и нажми F8»), кнопка мыши,
  интервал, число повторов / бесконечно, старт-стоп по хоткею и кнопкой.
- Статус-бар, базовая стилизация (QSS), трей-иконка со стопом.

**Критерий готовности:** пользователь без консоли настраивает и запускает
автоклик по точке, аварийный стоп работает.

## M3 — Модель сценариев (IR) и её исполнение
**Цель:** сценарии как данные — фундамент для Blockly.
- Схема IR: узлы `click`, `double_click`, `move`, `drag`, `delay`, `key`, `scroll`,
  `loop (repeat N/∞)`, `sequence`; `if` **зарезервирован** (условия — после M3),
  `while` появится вместе с условиями.
- Валидация и (де)сериализация JSON; версионирование формата (`version: 1`),
  ошибки списком с путями до полей.
- `interpreter.py`: обход IR → вызовы `InputBackend`, поддержка отмены/стопа.
- Сохранение/загрузка сценариев в файлы `.acl.json` (атомарная запись).
- Консольный запуск `scripts/run_scenario.py` (+ `--dry-run`), пример в `resources/examples/`.
- `recorder.py` — отложен (после Blockly/M5).

**Критерий готовности:** сценарий «клик → пауза → цикл 10×(движение+клик)»
исполняется из JSON без Blockly.

**Статус: ✅ выполнен (2026-10-26)** — 117 автотестов, `ruff` чист;
пример `resources/examples/click_pause_loop.acl.json` (22 действия).

## M4 — Визуальное программирование: Blockly
**Цель:** ключевая фича продукта — сборка сценариев из блоков.
- Vendored Blockly в `resources/blockly/`, страница редактора в `QWebEngineView`.
- Кастомные блоки (JS-определения + иконки/цвета): мышь, клавиатура, задержки,
  циклы; палитра категорий на русском.
- `QWebChannel`-мост: «Запустить» сериализует workspace в JSON → Python;
  события исполнения (стоп/ошибка/текущий блок) → подсветка в редакторе.
- Транслятор Blockly-JSON → IR; валидация ошибок пользователя (подсветка блока).
- Тулбар редактора: запуск, стоп, сохранить/загрузить, undo/redo.

**Критерий готовности:** пользователь собирает сценарий drag-and-drop,
запускает его и видит пошаговое выполнение; сценарий сохраняется и открывается.

**Статус: ✅ выполнен (2026-10-27)** — 180 автотестов,
`ruff` чист. Уточнения при реализации: `sequence` разворачивается в стек
(отдельного блока «группа» нет), hat-блок «старт сценария» не вводится
(IR не событийный), `if` в палитру M4 не выводится; `.acl.json` дополнительно
хранит `editor.workspace` для точного восстановления холста; `F5`/`F6`
работают контекстно, клики и сценарий взаимоисключающие. Приёмка пройдена,
ветка `feat/m4-blockly-editor` влита в `master`.

## M5 — Полировка и упаковка
**Цель:** продукт, который не стыдно раздать.
- Тёмная/светлая тема, единый визуальный стиль GUI и Blockly.
- Настройки (хоткеи, бэкенд ввода, язык) с сохранением в `%APPDATA%`.
- Юнит-тесты `core/` (IR, интерпретатор — с mock-бэкендом), смоук-тесты GUI.
- Логи и дружелюбные сообщения об ошибках.
- PyInstaller: сборка single-file .exe, иконка, проверка на чистой Windows.

**Критерий готовности:** .exe запускается без Python, все режимы работают,
тесты зелёные.

## Идеи на потом (backlog, вне roadmap)
- «Фоновые клики» без захвата курсора: `PostMessage` `WM_LBUTTON*` в выбранное
  окно — спайк после M2 (работает не во всех приложениях; второй независимый
  курсор в Windows невозможен, см. `AI_CONTEXT.md` ADR №12).
- Блоки «ждать появления картинки/цвета на экране» (openCV/template matching).
- Условные ветвления по состоянию экрана; переменные в сценариях.
- Библиотека готовых шаблонов сценариев.
- Ручная случайность (jitter координат и интервалов) для «человечности».
- Импорт/экспорт сценариев, шифрование.
