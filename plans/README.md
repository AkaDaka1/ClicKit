# Планы вех ClicKit

Планы — часть репозитория: здесь видно, как цель превращается в ADR, граф задач и проверяемый чекпоинт. Статус ✅ ставится только после выполнения критерия «done = …»; «запланировано» ≠ «сделано».

## Как читать

- Каждый план содержит: цель и критерий готовности, согласованные параметры, модули и интерфейсы, ADR, список коммитов, граф задач с зависимостями и волнами, чек-лист приёмки и журнал.
- Задачи выполняются по одной в отдельных сессиях по ID («выполни T1.2»); задача берётся только при закрытых зависимостях.
- Если работа уводит от плана — сначала правится план, потом код.

## Статус и ожидания

- **M0–M6** — сделано и влито в `master`; **M7** — в работе (T0.1: контракт
  API `docs/api.md`, T1.1: скелет сервиса, T1.2: БД и миграции, T2.1/T2.2:
  CRUD и crash-отчёты, T3.1: ключи и `request_id`, T3.2: Docker-образ
  сервиса), **M8–M11** — планы, а не реализация. Статус в таблице
  отражает только пройденные чекпоинты.
- Вехи идут последовательно: следующая начинается после критерия готовности
  предыдущей, кроме задач, явно помеченных как параллельные.
- План фиксирует порядок и проверяемые результаты, а не дату «всё готово».
  Одна сессия — одна задача по ID; незакрытая задача не считается сделанной.

## Порядок и границы

- **M6 не переделывается**: это инфраструктура сборки и тестов desktop-приложения. M7–M11 добавляют эксплуатацию отдельного сервиса и не дублируют задачи M6 (публикация образов, релизы desktop).
- **M7 → M8** — сначала работающий сервис, затем наблюдаемость: без сервиса метрикам нечего измерять.
- **M9 → M10** — сначала воспроизводимая инфраструктура, затем автоматическая доставка в неё.
- **M11** — после стабильной доставки: безопасность, нагрузка, бэкапы и учения. Это не блокер для первых трёх вех.
- Минимальный вертикальный срез для демонстрации: **M7 + M8** (сервис и его наблюдаемость). M9–M11 расширяют историю до эксплуатации в облаке.

## Принципы

1. Одна веха — одна проверяемая способность, а не набор несвязанных технологий.
2. Сначала минимальный рабочий срез, потом расширение; всё лишнее — в раздел «Вне вехи».
3. Критерий готовности измерим: команда, ответ, число, зелёный job, восстановленный бэкап.
4. Документация и ADR обновляются вместе с кодом, а не «потом».
5. Планы не выдаются за результат: статусы отражают только пройденные чекпоинты.
