## 1. Суть проекта

**ClicKit** (рабочее название репозитория до ребрендинга — AutoClicker) —
удобный и красивый автокликер для Windows с визуальным блочным
программированием в стиле Scratch / Blockly.

### Проблема аналогов
- Обычные автокликеры умеют только спамить кликами в одной точке.
- Продвинутые приложения со сценариями имеют сложный, перегруженный и
  недружелюбный интерфейс.

### Наше решение
Понятный UI, где сценарии кликов, перемещений мыши и задержек собираются из
наглядных визуальных блоков кода путём перетаскивания и комбинирования.
Два режима работы:
1. **«Простой режим»** — классический автокликер (интервал, кнопка, повторы) для тех, кому не нужны сценарии.
2. **«Режим сценариев»** — визуальный редактор блоков (Blockly) для сложных последовательностей.

### Целевая аудитория
Геймеры и обычные пользователи Windows, не имеющие навыков программирования.

## 2. Стек технологий

| Слой | Технология | Комментарий |
|---|---|---|
| Язык | Python 3.11+ | Типизация обязательна |
| GUI | **PySide6** | Выбран вместо PyQt6 из-за лицензии LGPL (без ограничений для проприетарного использования) |
| Визуальное программирование | Blockly + `QWebEngineView` | Blockly — локально (vendored в `resources/`), без CDN |
| Мост JS ↔ Python | `QWebChannel` | Обмен JSON между Blockly и движком |
| Эмуляция ввода | `pyautogui` + `pynput` | За абстракцией `InputBackend` (см. архитектуру) |
| Глобальные хоткеи | `pynput` | Слушатель в отдельном потоке |
| Сборка | PyInstaller (позже) | Один .exe для Windows |

## 3. Архитектура

### 3.1. Принципы
- **Слоистость:** GUI ничего не знает об эмуляции ввода; движок ничего не знает о GUI.
- **Потоки:** исполнение сценариев — только в воркере (`QThread`), GUI-поток никогда не блокируется.
- **Безопасность:** глобальный хоткеп аварийного стопа (по умолчанию `F6`) работает всегда,
  даже если сценарий «завис» в цикле.
- **Скрипт = данные:** сценарий существует в трёх формах:
  `Blockly-JSON → IR (наш внутренний JSON-формат) → последовательность команд движка`.
  GUI/Blockly и движок общаются только через IR.

### 3.3. Ключевые решения (ADR-конспект)
1. **PySide6, а не PyQt6** — лицензия LGPL, официальный Qt for Python, API практически идентичен.
2. **Blockly, а не самописный редактор** — зрелая библиотека drag-and-drop блоков;
   кастомные блоки описываются декларативно (JSON block definitions).
3. **Собственный IR вместо прямого исполнения кода из Blockly** — Blockly может
   генерировать Python-код, но выполнять произвольный код небезопасно и сложно
   отлаживать. IR ограничен нашим набором узлов (клики, движения, задержки, циклы,
   условия), валидируется и исполняется интерпретатором.
4. **Абстракция `InputBackend`** — pyautogui удобен для кликов/перемещений,
   pynput — для слушателей и низкоуровневого контроля; бэкенд выбирается конфигом,
   код движка от бэкенда не зависит.
5. **Название продукта — ClicKit** (2026-10-23, решение пользователя): игра слов
   «click it» + «kit» (набор/конструктор) — отражает суть: сценарии собираются
   как конструктор из блоков. GitHub-репозиторий — `ClicKit`; локальная папка
   будет переименована отдельно. README — двуязычный (EN сверху, RU снизу).

## 4. Правила кодинга

- Python 3.11+, **type hints везде** (включая возвращаемые значения).
- Форматирование: **ruff** (lint + format). Стиль — PEP 8.
- Имена в коде — **на английском**; комментарии, docstrings и документация — **на русском**.
- Docstring обязателен для всех публичных классов/функций/модулей.
- `core/` не импортирует `gui/` и `PySide6` (кроме `QtCore` для сигналов воркера —
  и то только в слое-адаптере).
- Никаких «божественных» классов: файл > ~300 строк — повод разбить.
- Одна фича = одна ветка/коммит; сообщения коммитов в формате `type: subject`
  (feat/fix/docs/refactor/test/chore), на русском или английском — последовательно.
- Конфиг приложения (хоткеи, выбранный бэкенд, тема) — через единый модуль
  настроек с сохранением в JSON в `%APPDATA%`.
- Любой пользовательский ввод (в т.ч. JSON из Blockly) валидируется перед исполнением.
- **`.gitignore` всегда актуален:** добавил инструмент или процесс, порождающий
  артефакты (кэши, сборки, логи, локальные конфиги, пользовательские данные) —
  сразу дополни `.gitignore` соответствующими шаблонами. Случайно попавшие в
  индекс артефакты удаляй через `git rm --cached <путь>`.

## 5. Глоссарий

- **IR (Intermediate Representation)** — внутренний JSON-формат сценария.
- **Бэкенд ввода** — реализация `InputBackend` (pyautogui или pynput).
- **Простой режим** — классический автокликер без блочного редактора.
- **Редактор** — вкладка с Blockly для сборки сценариев.
- **Пикер** — инструмент «наведи и нажми хоткей, чтобы захватить координаты».
